04How it works

Keep the snapshots. Rebuild the archive.

Sources save dated snapshots. Build combines them in SQLite. Agents search through read-only tools.

  1. 1

    Fetch.

    commonplace sync takes one snapshot per source per day into data/raw/<source>/<date>/. Each one is written through a .partial directory and made read-only, so a crash never leaves half a snapshot. On a Mac, commonplace install runs it at login and when Messages changes, and the Claude Code plugin runs it when a session ends. A source with today's snapshot waits for tomorrow; an export source updates when you add a newer export.

  2. 2

    Build.

    Every build starts from empty and replays every snapshot into one SQLite database. The same raw/ always gives the same database, so you can fix a source and rebuild years of history.

  3. 3

    Read.

    The CLI and the MCP server read the same store, read-only: search, timeline, show, stats, and sql for you.

05Privacy

Choose what you collect and expose.

Data stays in your local data/ folder, which the template keeps out of git. Connected agents can read everything in the built archive, and may send what they read to their model provider.

  • is everything the archive holds. A source you leave off is never read.
  • keeps matching messages out of new snapshots.
  • keeps rows out of the database. Raw snapshots stay on disk.
  • Run commonplace build after changing sources or redact.

06Yours

Your repo, your sources, your archive.

About 1,400 lines in the core, plus the sources. Bun and SQLite, with no runtime packages. Read it in an afternoon. Change anything.

Read it.

src/ is ten small files. One schema, one builder, one store, two doors.

src/schema.ts   things, events, links, verbs
src/build.ts    replays snapshots; the only writer
src/store.ts    every read
src/cli.ts      one door
src/mcp.ts      the other

Change it.

A source is one file with two halves: fetch copies what the service gives, rows turns one snapshot into things, events and links.

export default defineSource({
  name: "bookmarks",
  fetch: async ({ dir }) => { … },
  rows: async function* ({ dir }) { … },
});

Keep it.

Your repo, your data, your rules. Updates to the template never touch data/.
