02 why

This is how an agent learns your judgment.

Your taste isn't in any one file. It's in what you saved, what you starred, what you rejected, and how you asked last time. An agent that can search that stops guessing what you mean.

The more an agent knows about you, the less you have to say, and the more you can hand it.

04 how it works

Three steps, one direction.

Fetch writes. Build reads snapshots. Agents read the database through one door. Nothing goes the other way.

  1. Fetch.

    commonplace sync takes one snapshot per source per day into data/raw/<source>/<date>/. Each one is written through a .partial directory and made read-only, so a crash never leaves half a snapshot. On a Mac, commonplace install runs it on its own, and the Claude Code plugin runs it whenever a session ends.

  2. Build.

    Every build starts from empty and replays every snapshot into one SQLite database. The same raw/ always gives the same database, so you can fix a source and rebuild years of history.

  3. Read.

    The CLI and the MCP server read the same store: MCP shows only the sources you allow, the CLI shows you everything. search, timeline, show, stats, and read-only sql for you.

05 privacy

What agents see is up to you.

Your data lives in data/, which never enters git. Agents never open the database. Over MCP they see only the sources you allow; the CLI shows everything to whoever runs it.

  • is the list of sources any MCP client may read. The --sources github flag on commonplace mcp narrows it for one client. imessage is in sources but not in mcp, so your messages stay local until you add it.
  • rules keep rows out of the archive entirely. They're never written.
  • A reader sees a row only if it may read every source that contributed to it, so a hidden source can't leak through a merge.

06 yours

A template you own. Not an app you install.

About 1,300 lines of TypeScript in your own repo, next to your own data. Read it in an afternoon. Change anything.

Read it.

src/ is ten small files. One schema, one builder, one store, two doors.

src/schema.ts   things, events, links, verbs
src/build.ts    replays snapshots; the only writer
src/store.ts    every read, filtered by what you allow
src/cli.ts      one door
src/mcp.ts      the other

Change it.

A source is one file with two halves: fetch copies what the service gives, rows turns one snapshot into things, events and links.

export default defineSource({
  name: "bookmarks",
  fetch: async ({ dir }) => { … },
  rows: async function* ({ dir }) { … },
});

Keep it.

Your repo, your data, your rules. Updates to the template never touch data/.

my-commonplace/
  commonplace.config.ts   yours
  sources/                yours, plus ours
  data/                   yours, never in git
